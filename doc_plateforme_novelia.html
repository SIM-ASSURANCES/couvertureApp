Vue d'ensemble

Une application unique de micro-assurance couvrant trois branches métier, distribuée par QR code, avec paiement mobile et espace client en libre-service.

Branches produits

  • Assurances Accidents et Dommages — branche principale : RelaxMoto/RelaxAuto, RelaxAccidents (Frais Médicaux, générale), RelaxVoyage, SecurHome+, SecurPro Dommages, Incendie/Accident (modèles historiques).
  • Relax — branche d'origine, pages admin toujours actives mais retirées du menu principal.
  • Assurances IMF — distribution via un réseau zones → agences → agents pour les institutions de micro-finance (SecurPro, SecurStock, Coups Durs, SecurÉcolte), sans passerelle de paiement en ligne.

Acteurs de la plateforme

Agent IMF
Réseau à 5 rôles (agent → chef de zone), branche IMF.

Espace en libre-service : contrat, renouvellement, sinistre, réseau de soins.

Architecture technique

Backend et frontend séparés, chacun packagé en image Docker et déployé indépendamment.

CoucheChoix technique
BackendNode.js + Express (TypeScript, modules ESM)
Base de donnéesPostgreSQL via Prisma ORM
AuthentificationJWT + bcryptjs, validation des entrées avec zod
Rendu PDF / imagepuppeteer-core (Chromium headless) — contrats et cartes
Tâches planifiéesnode-cron (relances SMS, échéances)
FrontendReact 19 + TypeScript + Vite + React Router 7

Déploiement

Le VPS est piloté par Dokploy derrière un reverse-proxy Traefik. Deux images sont publiées sur GHCR :

  • ghcr.io/sim-assurances/couvertureapp-backend
  • ghcr.io/sim-assurances/couvertureapp-frontend

Chaque image est versionnée (vN) en plus du tag latest. Au démarrage, le conteneur backend exécute prisma db push puis un seed idempotent (compte Super Admin, catalogue produits). Le docker-compose.yaml du dépôt sert de référence locale — la configuration réelle de production est éditée dans Dokploy.

03

La carte de prise en charge

Un visuel individuel remis au client après paiement confirmé, reproduisant la mise en page de la carte physique fournie par Novelia — générée à la volée, pas imprimée à l'avance.

Composition visuelle

La carte est composée en HTML/CSS (gabarit fixe 1013 × 638 px) puis rendue en image PNG par Chromium headless. Elle affiche :

  • le logo Novelia et le titre « Carte individuelle Accidents » ;
  • une bannière de garantie, dont le libellé varie par produit — FMP pour RelaxAccidents Frais Médicaux, DÉCÈS / IPT pour RelaxVoyage, CAPITAL GARANTI pour les autres ;
  • la photo du souscripteur (selfie déposé à la souscription), son matricule, nom, prénoms, date de naissance, sexe et date d'entrée ;
  • le pied de page SIM Assurances.

Deux prérequis conditionnent sa disponibilité : la souscription doit être confirmée (paiement Wave validé) et un selfie doit avoir été déposé comme document justificatif.

backend/src/services/carteRender.ts 
// Libellé de la garantie affichée sur la bannière, variable par produit
function garantieAffichee(produitCode: string) {
  if (produitCode === "relaxaccidents_fraismedicaux") return "FMP";
  if (produitCode === "relaxvoyage") return "DÉCÈS/IPT";
  return "CAPITAL GARANTI";
}

04

Intégration API Novelia

Le point que ce document doit poser clairement : la connexion à une véritable API Novelia n'existe pas encore dans le code.

État actuel : mode simulé (stub)

Le service backend/src/services/novelia.ts ne contacte aucun serveur Novelia. Il génère localement un numéro de carte et enregistre une ligne de suivi en base — que la clé d'environnement NOVELIA_API_KEY soit renseignée ou non change actuellement rien au résultat.

Ce que fait réellement le code aujourd'hui

backend/src/services/novelia.ts 
export async function genererCarte(souscriptionId: string) {
  const existante = await prisma.carte.findUnique({ where: { souscriptionId } });
  if (existante) return;

  // Avec ou sans clé, le comportement est identique pour l'instant :
  // TODO(intégration NOVELIA réelle) — appeler l'API une fois la
  // documentation/clé fournie (endpoint, format requête/réponse).
  await prisma.carte.create({
    data: { souscriptionId, numero: newNumeroCarte(), statut: "generee" },
  });
}

Deux choses distinctes portent le nom « Novelia » dans la plateforme, et il est utile de ne pas les confondre :

  1. Le visuel de la carte (section 3) — un gabarit HTML/CSS et un logo qui reproduisent manuellement le design de la carte physique Novelia. C'est fonctionnel, mais ce n'est pas une intégration API : aucune donnée n'est récupérée depuis Novelia pour la construire.
  2. L'annexe « réseau de soins » (section 5) — un fichier de données fourni par Novelia, importé une fois, pas interrogé en direct.

Le modèle Prisma Carte porte déjà un champ noveliaRef réservé à une référence renvoyée par leur système — il n'est écrit nulle part dans le code actuel, ce qui confirme qu'il attend la vraie intégration.

Variables d'environnement

VariableDéclarée dansEffet actuel
NOVELIA_API_KEY .env.example, docker-compose.yaml, novelia.ts Bascule une condition dont les deux branches produisent aujourd'hui le même résultat.
APP_PUBLIC_URL carteHtml.ts Non spécifique à Novelia, mais sert à construire l'URL du logo affiché sur la carte.

Pour engager la vraie intégration

Trois éléments manquent aujourd'hui pour remplacer le stub par un appel réel :

  • la documentation d'API fournie par Novelia (endpoint(s), méthode d'authentification, format de requête et de réponse) ;
  • une clé d'accès valide, à placer dans NOVELIA_API_KEY ;
  • une décision métier sur ce que l'appel doit accomplir concrètement — immatriculer le bénéficiaire dans le système Novelia, récupérer une référence de carte officielle à stocker dans Carte.noveliaRef, ou autre chose selon ce que propose leur API.

Une fois ces éléments réunis, le point d'entrée à modifier est unique : la fonction genererCarte() dans backend/src/services/novelia.ts, appelée depuis la confirmation de paiement Wave (RelaxMoto/RelaxAuto) et depuis le renouvellement Relax historique.

Réseau de soins

Un annuaire de prestataires conventionnés, distinct de la carte et de toute connexion API — un fichier de données statique fourni par Novelia.

85

662

Les données vivent dans frontend/public/reseau-soins.json — pas de base de données, pas d'appel API : le fichier est servi tel quel et chargé à la demande (≈ 140 Ko) depuis l'onglet « Réseau » de l'espace client (ReseauSoins.tsx), avec recherche texte, filtres par catégorie/commune et pagination par 40. Il n'apparaît pas sur la carte visuelle elle-même — c'est une ressource consultée à côté.

Pour mettre à jour l'annuaire

Remplacer frontend/public/reseau-soins.json à partir du fichier fourni par Novelia et redéployer le frontend — aucune migration ni changement de code nécessaire.
